# Reference

Historical artifacts, kept for provenance. **Nothing here is read by the code or by any test**, and
nothing here is regenerated. Do not treat these as the shape the current code should produce.

## `Green_Button_Peak_Values-python-2026-07-16.xlsx`

The workbook the Python implementation produced, before the Rust rewrite. It is the only artifact in
this repository that cannot be regenerated from the code, which is the whole reason it is kept.

- Produced by `docs/green_button/archive/python/build_peak_values.py` on 2026-07-16.
- From `data/TH_Electric_Usage_23-11-2024_to_24-06-2026.XML`, the same input the current tool takes.
- sha256 `6ea76c29efbcf4a613a659abf72efb35b6eb97c8fdb0e20a07cdd29ad1b2a5f0`.

Its figures are the ones that were reconciled against real Toronto Hydro invoices over many months,
and its period ending 2026-06-23 ties out to the June 2026 bill to the milli-kWh. That reconciliation
is what made it a usable oracle for the one-time port gate recorded in
`../../maintenance-manual.md`, "The port gate — run once, recorded here, then removed" — 21 billing periods, 19 shared columns, 399 cells, no differences.

That gate has been run and recorded, and this file has no job left. Its formatting is **not** the
current standard: it stores a row height on all 13,924 of its rows because that is what LibreOffice
writes, its two sheet titles are different sizes, and its `Interval_values` data rows differ from its
`Peak_values` data rows for no reason. See `../../maintenance-manual.md`, "Row heights: three, and only three".
